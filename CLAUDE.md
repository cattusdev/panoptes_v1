# Panoptes v1.0

ASP.NET Core 8 **JSON API** (Identity + PostgreSQL + EF Core) with a **React + Tailwind + shadcn/ui** single-page app (`Panoptes_v1.Client`). There are no Razor views. Commands, the definition of done and common traps: [AGENTS.md](AGENTS.md).

**Product docs:** this boilerplate is the base for **Hankatt Operations** (internal ops platform). Requirements, business rules, UX standard and the gated roadmap live in [docs/](docs/README.md). Follow the gates there: no new module is implemented before its architecture section and UX brief are approved.

## Structure
- `Panoptes_v1/` backend: `Api/` controllers (`/api/auth`, `/api/account`, `/api/users`, `/api/roles`, `/api/audit-logs`, `/api/dashboard`, `/api/media`, `/api/branding`, `/api/settings`, `/api/jobs`), `Services/` (`AdminGuard`, `AccountEmails`, `EmailSender`, `AppUrls`, `BusinessClock`, `Access/`, `Jobs/`, `Media/`, `Settings/`), `Data/` (DbContext with audit logging, `AuditContext`), `Middlewares/GlobalExceptionHandler`. Serves the built client from `wwwroot/spa` as the fallback for every non-API route.
- `Panoptes_v1.Client/` React app: `src/pages/{auth,account,admin}`, layouts in `src/components/layout` (AuthLayout, ConsoleLayout + our own AdminSidebar; navigation comes from the registry `layout/nav.ts` (six groups, collapsible, only allowed items, empty groups hidden), which also feeds the `CommandPalette` (Ctrl/⌘+K, topbar trigger); a new module = one `navItems` line + `common:nav.*` label + its route wrapped in `requires(permission)` in `router.tsx` (`RequirePermission`: direct URL without the permission shows an in-console "no access" state; UX only, the server enforces)), shared admin pieces in `src/components/admin` (DataTable, TablePagination, ColumnsMenu, StatusBadge, MoneyText, ConfirmDialog, OptionSelect, PageHeader/RouteTabs, SettingsCard, DangerZone, StatCard...), form pieces in `src/components/form`, media pieces in `src/components/media` (`MediaBrowser` + `browser-state` for URL or local state, `FolderTree`, `MediaUploader` = our FilePond wrapper, lazy via `LazyMediaUploader`, `MediaDetailsSheet`, `UploadDialog`; reusable in any form: `MediaPicker` dialog, `MediaField` form control, `MediaImage` responsive image), API hooks in `src/lib/*-api.ts` (uploads: `lib/media-upload.ts`). Console routes are lazy-loaded in `src/router.tsx`.
- Media (`Services/Media`, `Api/Media*`): every file enters through `MediaService.IngestAsync` (sniff real type, limits, NetVips re-encode + thumb/medium/large WebP, metadata stripped) and is stored via `IMediaStorage` (`FileSystemMediaStorage` = local `App_Data/media`, or `S3MediaStorage` = Cloudflare R2/S3 with a public and a private bucket; `Media:Provider`; never in `wwwroot`). Uploads use our chunk protocol (`/api/media/uploads`: POST, PATCH with `Upload-Offset`, HEAD, DELETE). Public files are served from `/media/p/...` (static, immutable cache) or straight from the public bucket (`Media:S3:PublicBaseUrl`); private ones from `/media/{id}/{version}/{variant}` after `MediaAccess` checks (404 when not allowed). Limits live in `MediaOptions` (`Media` section). `MediaCleanup` (run hourly by `MediaCleanupService`, `Media:CleanupIntervalMinutes`, 0 = off) removes stale upload sessions/temp files, trash older than `TrashRetentionDays`, versions over `MaxVersions`, unused avatars and orphan files, and moves files left in the wrong public/private area back.
- File attachments (`Services/Media/MediaAttachments`, table `MediaAttachments`): one library file can be linked to many records (`EntityType`/`EntityId`, plus the record's `ProjectId` and an optional `RequiredPermission`). **The strictest link wins**: every media query (list, search, trash, details, versions, folder counts, file delivery, branding/replace lookups) goes through `MediaAttachments.VisibleTo(query, User)`, so a file in a project you can't see is invisible everywhere. Project visibility comes from `IProjectAccess` (`Services/Access`); until the Projects module exists it is `AdminOnlyProjectAccess` (fail closed). Attached files can't be public, trashed, purged, undone or deleted with their folder (`MediaUsage.BlockingUsageAsync` / `PublicBlockAsync`); unlinking removes only the link.
- Background jobs (`Services/Jobs`, table `BackgroundJobs`, admin API `/api/jobs`): `JobQueue.EnqueueAsync(type, payload, idempotencyKey, runAtUtc)` inserts with `ON CONFLICT DO NOTHING`, so the same key never runs twice, and it joins the open transaction (outbox: the job exists only if the change that caused it was saved). `JobProcessor` claims jobs with `FOR UPDATE SKIP LOCKED`, retries with backoff (`Jobs` section: `PollSeconds` (0 = off), `LeaseMinutes`, `DefaultMaxAttempts`, `RetryDelaySeconds`) and records `LastError`. Admins see them at `/admin/jobs` (Admin only, `RequireAdmin` / nav `adminOnly`): failed-jobs alert, status/type filters, details with last error and payload, retry/cancel, and bulk retry (`POST /api/jobs/retry`, all or nothing). A handler implements `IJobHandler` (register `AddScoped<IJobHandler, X>()`), must re-check that its work is still needed, and must not put secrets in the payload. Emails from jobs: `queue.EnqueueEmailAsync(...)`; links come from `AppUrls` (`App:PublicBaseUrl`, required in production and for jobs).
- Data integrity: the audit log (`ApplicationDbContext.SaveChanges*`, sync and async, one transaction) records the user, or the `Source` set with `AuditContext.Use("jobs:...")` (jobs, CLI, cleanup), plus the request's `TraceId`. Never-audited columns are listed per entity type (`SensitiveColumns`) or marked `[AuditIgnore]`; concurrency tokens are skipped. `ExecuteUpdate`/`ExecuteDelete` bypass the audit: use them only for non-audited tables. Mutable entities get `public uint RowVersion` + `.IsRowVersion()` (Postgres `xmin`, no column); a conflicting save throws `DbUpdateConcurrencyException`, which `GlobalExceptionHandler` turns into a 409 the client shows as a toast. Entities implementing `IHasTimestamps` (`Models/`) get `CreatedAt`/`CreatedById`/`UpdatedAt`/`UpdatedById` set by the DbContext on save (never by hand; user `null` = job/CLI; not repeated in the audit diff).
- Human references (`Services/References.cs`): `ReferenceGenerator.NextAsync(ReferenceFormats.Client)` → `CL-0042`, yearly formats → `CHG-2026-0153` (business year). Numbers come from the `Sequences` table with a row lock, so call it **inside the transaction that saves the record** (it throws otherwise): a rolled-back save gives the number back, no gaps, no duplicates.
- Business dates (`Services/BusinessClock`): server-side date maths (due dates, renewals, "today") use the Settings → General time zone, else `Europe/Athens`. Store instants as UTC and whole days as `DateOnly`.
- Settings (`/admin/settings`, `Settings.*` permissions): one layout with a vertical section nav. Sections live in the client registry `pages/admin/settings/sections.ts` (+ one route in `router.tsx`); pieces are `SettingsNav` and `SettingsCard` (with `footer`) in `components/admin`. Backend values are stored as JSON per section in the `AppSettings` table through `Services/Settings/SettingsService` (`GetAsync<T>`/`SaveAsync<T>`; a new section is just a new `ISettingsSection` class, no migration). Secrets (the SMTP password) are encrypted with Data Protection (keys in `App_Data/keys`), stored in the `Secret` column, never returned to the client and never audited. Settings → Finance (`FinanceSettings`: `DefaultVatRate` 24, `TrackingStartDate` 2026-12-01) is changed only with `Finance.Settings` (not `Settings.Edit`); a new tracking start date needs a reason, kept in the audit log.
- Lists: `DataTable` (TanStack Table v9 underneath) takes `sort`/`onSortChange` (server-side, `sort=key|-key`), `columnVisibility` (`useColumnVisibility(tableId)` + `ColumnsMenu`, columns with a `label` can be hidden) and `bulkActions` (row selection on the current page + a bulk bar). Filters, page, page size and sort live in the URL through `useUrlFilters([...keys])` (`hooks/`); `TablePagination` takes `onPageSizeChange`. Server side, every list uses the helper in `Api/ApiContracts.cs`: a `[FromQuery]` subclass of `ListRequest` (`search`, `sort`, `page`, `pageSize` + typed filters, so a bad value is a 400), `SortMap<T>(default, tieBreaker)` (whitelisted fields, always ends with the unique tie-breaker), `.ToPagedAsync(request)` (clamped paging) and `.Map(ToDto)`; search with `EF.Functions.ILike(x.Name, Like.Contains(term), Like.EscapeCharacter)` so `%`/`_` are literal (without the escape argument Npgsql writes `ESCAPE ''` and such searches match nothing).
- Forms: react-hook-form + zod through `lib/forms.ts` (`useZodForm(schema, defaults)`, `schemas.*` incl. `required(...)` for inputs that start as null, `applyServerErrors(form, error)` maps ProblemDetails to fields). zod messages are translated globally (`common:validation.*`), so schemas live at module scope. Render fields with `FormField` (label + control + error/description); inputs: `MoneyInput` (both `1.234,50` and `1,234.50`, NaN = invalid), `DatePicker` (DateOnly `yyyy-MM-dd`), `Combobox`, `MultiSelect`. Wizard stepper and drafts come with the onboarding wizard.
- Status and money: map every status to a tone in `lib/status.ts` (`danger`/`warning`/`info`/`success`/`neutral`/`historical`, docs/ux/README.md) and show it with `StatusBadge`; never pick badge colours per page. Amounts are shown with `MoneyText` (Intl in the user's language, `null` = "Unknown", `credit`). `Alert` has `info`, `warning`, `success`, `error`, `destructive`.
- `/admin/dev/kit` is a test-only page (it exists only when `Diagnostics:EnableTestEndpoints` is on) where the E2E tests exercise shared components that no screen uses yet.
- Dates: always display them with `<DateTime value mode="date|dateTime|relative" />` (`components/admin/DateTime`) or `useDateFormat()` (`lib/dates.ts`; `.day()` for DateOnly values), never `toLocaleString()`: they follow Settings → General (date format, 12/24h, time zone).
- Languages (English, Greek; English is the source and fallback): **no hard-coded UI text**.
  - Client: react-i18next (`src/i18n`). One JSON per namespace and language in `src/i18n/locales/{en,el}/` (`common`, `auth`, `account`, `admin`, `media`, `settings`); `el` is typed against `en`, so a missing Greek key fails `tsc`, and keys are typed in `t()`. English ships in the bundle, Greek loads as its own chunk. Components use `useTranslation('<ns>')`; non-component code stores keys or calls `i18n.t` at use time (never at module load). Whole sentences with `{{vars}}`, `_one`/`_other` plurals, `<Trans>` for links inside text.
  - Which language: the user's choice (`UserProfile.Language`, My account → Profile, `PUT /api/account/language`) → a visitor's choice (footer `LanguageSwitcher`, localStorage) → the app default (Settings → General, `GeneralSettings.DefaultLanguage`). `useLanguageSync` applies it; `lib/api.ts` sends it as `Accept-Language`.
  - Server: `IStringLocalizer<SharedResource>` with the English text as key and Greek in `Resources/SharedResource.el.resx` (API messages, validation, Identity errors via `LocalizedIdentityErrorDescriber`). `UseRequestLocalization`: Accept-Language, then the app default. Emails go out in the recipient's language (`AppLanguages.Use(...)`).
  - Dates/numbers follow the language (`Intl`): month names, AM/PM, relative times.
- Profile photos: uploaded with purpose `Avatar` (any signed-in user, square crop) then set via `PUT /api/account/avatar` (`Services/ProfileService`); DTOs expose `avatarUrl`. Branding (`/api/branding`, `Settings.*` permissions): app name, logo and favicon picked from the library (made public, protected from trash/private by `MediaUsage`); the client reads it with `useBranding()`.
- `Panoptes_v1.E2E/` Playwright + NUnit tests against the real app and a throwaway `Panoptesv1_E2E` database.
- `Panoptes_v1.Tests/` domain + architecture tests (ARCHITECTURE §12): the real services in-process against a throwaway `Panoptesv1_Test` database, no browser. `DomainTest` gives each test its own service provider, a settable `TestClock`, `SignIn(userId)` and `WithScopeAsync`/`WithDbAsync`. Architecture tests check client/server permissions, `RowVersion` = `xmin`, explicit access on every endpoint, `ListRequest` on paged endpoints, escaped `ILike`, and module boundaries (active from the first `Panoptes_v1.Modules.*`).

## Running
- First time: connection string in user secrets (`dotnet user-secrets set ConnectionStrings:DefaultConnection "..."` in `Panoptes_v1/`), then `dotnet run -- db:migrate`, `dotnet run -- admin:create you@example.com` (`Services/SetupCommands`; password from `ADMIN_PASSWORD` or asked for) and `dotnet run -- roles:seed` (creates the missing default roles of `Constants/DefaultRoles`; existing roles are never changed). Passwords and keys never go in `appsettings.json`.
- Production: set `App:PublicBaseUrl` (e.g. `https://ops.example.com`), so email links never come from the request's Host header; the app logs a warning at startup when it is missing.
- Backend: `dotnet run --launch-profile https` in `Panoptes_v1/` → https://localhost:7770 (builds the client automatically if `wwwroot/spa` is missing).
- After client changes: `npm run build` in `Panoptes_v1.Client/`, or for hot reload `npm run dev` → http://localhost:5173 (proxies `/api` and `/img` to the backend).
- Media on Cloudflare R2: fill `Media:S3` (keys in user secrets / env vars, e.g. `Media__S3__SecretKey`), run `dotnet run -- media:migrate` in `Panoptes_v1/` (copies local files to the buckets, safe to re-run), then set `Media:Provider` to `S3` and restart.
- Emails: `Services/AccountEmails` builds the account emails (links point to React pages). `EmailSender` (MailKit) picks, in order: `Email:PickupDirectory` (JSON files, the E2E tests use it) → the custom SMTP from Settings → Email → `SmtpSettings` (user secrets; `Security` = `None`/`StartTls`/`SslOnConnect`/`Auto`) → in Development `App_Data/emails`. For local mail use Mailpit (SMTP `localhost:1025`, `Security` `None`, inbox at http://localhost:8025).

## UI / UX: think before designing
For any UI decision, and especially for **UX flows** (sign-in, onboarding, multi-step forms, tables with actions, settings, destructive actions, empty/error states):
1. **Stop and think first.** Don't jump straight to markup.
2. **Look at how well-known apps with clean, modern design solve the same problem** (e.g. Linear, Vercel, Stripe Dashboard, GitHub, Clerk, Supabase, Notion). Note what they do for layout, flow, wording, and feedback.
3. Then decide and apply, briefly stating which references informed the choice.

Design language: light public/auth pages (off-white, near-black primary, lavender pills, mauve accent, dark brand panel); dark neutral console with mauve primary and tinted status badges. Use shadcn components (`src/components/ui`, add more with `npx shadcn@latest add <name>`) instead of hand-rolled ones; build shared pieces once and reuse them. The admin **sidebar is our own component**, not shadcn's. No dead links or controls that do nothing.

## Security rules
- No public site, no self-registration, no self-service password reset: `/` redirects to the dashboard (or My account) when signed in, else to `/login`. Accounts and new passwords come only from an administrator (Users → Create user / Reset password).
- Admin = superuser; every user/role action goes through `Services/AdminGuard` (never manage or grant above your own permissions).
- State-changing requests require an antiforgery token (the client's `lib/api.ts` sends `X-XSRF-TOKEN` from the `XSRF-TOKEN` cookie).
- Any Identity call that rotates the security stamp for the *current* user (2FA changes, password, email, phone) must be followed by `RefreshSignInAsync`, or the user gets signed out.
- Media: shared library (`Media.View` sees all); edit/delete only your own files unless `Media.ManageAll`. Never trust file names or browser-side checks; validation and resizing happen on the server.
- Errors never leak internals: `GlobalExceptionHandler` returns ProblemDetails with a reference id (API) or a plain error page.

## Testing
Every feature/fix gets Playwright E2E coverage in `Panoptes_v1.E2E`; backend business rules also get domain tests in `Panoptes_v1.Tests` (one per acceptance scenario S1–S20 that is backend logic). Run `dotnet test Panoptes_v1.Tests` and `dotnet test Panoptes_v1.E2E` before calling work done. Screenshots for a visual check: `dotnet test Panoptes_v1.E2E --filter "Category=Screenshots"`. S3 storage (needs Docker, runs Adobe S3Mock): `--filter "Category=S3"`.
